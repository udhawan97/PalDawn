# PalDawn v0.1.0 performance report

Measured on 2026-08-20 against candidate commit
`4620908ac43745cb5a631d5876c65cd56690f823`. The immutable measured app tree is
`360908c92de9fd330bfb847ec1e5c259c6c4126b`; later release-only documentation
and graph-index commits must preserve that tree or repeat this measurement.

## Method

The production build was served with `vite preview`. The journey was started,
paused, and scrubbed to three representative transition points. Each point was
given 120 `requestAnimationFrame` callbacks of warm-up, then measured in three
runs of 180 callbacks. Results below use browser-supplied frame timestamps. The
timer was quantized to integer milliseconds, so a nominal 60 Hz cadence appears
as a 16/17/18 ms distribution rather than an exact 16.67 ms line.

The on-screen telemetry is an application estimate over its rolling 240-frame
window. Its draw-call and triangle readings are instantaneous renderer counters,
not a complete frame capture. Browser CPU/GPU memory was unavailable and is not
estimated here.

## Build and gate result

- Core JavaScript: 1,214.33 KB minified, 333.68 KB Vite-reported gzip;
  the release-contract calculation is 329,340 bytes gzip.
- CSS: 16.21 KB minified, 4.40 KB gzip.
- The 500 KB gzip JavaScript budget passes.
- The renderer counters are far below the draw-call and triangle ceilings, but
  they are lightweight runtime readings rather than a GPU frame capture.
- A stable 60 Hz mean was observed at all three points. The strict desktop
  `p95 <= 16.7 ms` proof gate is **not confirmed** because the measured p95 is
  18 ms with integer-millisecond WebKit timestamps.
- The 30 fps / 33.3 ms mobile floor, a physical mobile GPU, fast-4G first-scene
  timing, Safari fidelity, and browser memory remain **not evaluated**. The
  responsive journey was separately exercised with an emulated mobile WebKit
  viewport; that is interaction coverage, not physical-device performance.

This report supports a bounded v0.1 systems release. It does not validate future
anatomy, pathology, or clinical-content performance.
